01
배경과 기회

제도는 바뀌었고,
사람들은 길을 잃었다

2026년 10월 검찰청 폐지로 형사사법 절차가 경찰·중대범죄수사청·공소청 3원 체계로 개편됐다. 처음 고소하는 사람에게는 더 어려워졌다.

제도가 바뀌었다

수사·기소가 분리되며 사건을 맡는 기관이 셋으로 나뉘었다.

국민은 더 헤맨다

중수청과 경찰의 구분, 송치·이첩 같은 용어, 끝을 알 수 없는 처리 기간이 불안을 키운다.

행정도 막힌다

잘못 접수된 고소장의 이송과 “내 사건 어디 있나요?” 같은 반복 문의가 민원을 짓누른다.

04
화면 설계

여섯 개의 화면, 하나의 원칙

모든 화면은 “법률 용어 없이 다음 행동이 보이는가”를 기준으로 설계했다. 번호는 기능 명세와 대응한다.

1234
SCR-01

메인 홈

법을 모르는 사용자가 메뉴를 헤매지 않고, 원하는 행동을 1초 만에 고르게 한다.

FUNCTIONAL SPECIFICATION
1
AI 검색 바
자연어 입력 → 의도 분류 후 진단·추적 화면으로 이동
2
3대 퀵 카드
진단·추적·신청 진입, 진행 중 사건은 상태 요약 노출
3
절차 가이드
카드뉴스 가로 스와이프, 제도 개정 시 CMS로 즉시 갱신
4
하단 탭
홈 · 진단 · 내 사건 · 신청 · 프로필 5개 고정
UX DESIGN RATIONALE
메뉴 대신 질문으로 시작

사용자는 ‘어느 기관’이 아니라 ‘무슨 일’을 안다. 검색 바를 최상단에 두어 상황을 그대로 말하게 했다.

속마음을 카드 제목으로

‘관할 확인’ 대신 ‘어디로 가야 할까?’처럼 사용자의 말로 써서 첫 클릭의 망설임을 줄였다.

SCR-02

관할 진단

어려운 질문 없이, 클릭 세 번으로 담당 기관을 판별한다.

FUNCTIONAL SPECIFICATION
1
질문 Step 1~3
피해 유형 → 피해 금액 → 상대방 신분, 한 화면에 한 질문
2
선택 카드
단일 선택 필수, 미선택 시 ‘다음’ 비활성 · ‘잘 모르겠어요’ 제공
3
용어 ‘?’ 아이콘
탭 시 쉬운 말 툴팁, 공통 용어 사전 API 호출
4
진행률 · 이전/다음
이전으로 가도 응답 유지, 마지막 단계에서 판별 API 요청
UX DESIGN RATIONALE
MBTI 테스트처럼 가볍게

한 화면에 질문 하나, 큰 카드로 답하게 해 법률 상담이 아니라 퀴즈처럼 느끼게 했다.

버튼은 엄지 닿는 곳에

진행률과 이전/다음을 하단에 모아 한 손 조작을 보장하고, 남은 단계를 늘 보이게 했다.

판별 결과를 이유와 함께 알려주고, 대화로 고소장을 완성한다.

FUNCTIONAL SPECIFICATION
1

판별 근거를 쉬운 말 한 문장으로, ‘자세히’에서 원문 조항

대화형 작성
육하원칙 질문 6개 순차 제시, 날짜·금액 형식 검증
4
증거 첨부
드래그 앤 드롭 · JPG/PNG/PDF, 파일당 20MB 이하

‘왜 경찰인가’를 한 문장으로 붙여, 바뀐 제도에 대한 불신과 재문의를 줄였다.

서식이 아니라 대화

‘범죄사실’ 칸 대신 ‘얼마를 입금했나요?’라고 물어 용어를 몰라도 고소장이 완성된다.

FUNCTIONAL SPECIFICATION
1

UX DESIGN RATIONALE
익숙한 멘탈 모델 빌리기

20대에게 가장 익숙한 추적 경험인 택배 조회를 차용해, 배우지 않아도 ‘지금 어디’를 읽게 했다.

기관은 색으로 기억

경찰 · 중수청 · 공소청에 고유 색을 줘, 이첩되면 색이 바뀌는 것만으로 변화를 알아채게 했다.

SCR-03 · 필수 항목 누락

고소장이 덜 채워졌을 때

빈 항목을 쉬운 말로 짚어주고 제출을 막는다. 부실한 고소장이 기관 부담으로 돌아가지 않게 하는 마지막 관문이다.

리스크왜 문제인가대응 설계
관할 판별의 책임판별이 틀리면 피해자가 시간을 잃고, 앱이 신뢰를 잃는다‘판정’ 대신 ‘안내’로 표현, 애매하면 판별 보류 후 가까운 창구 연결
민감정보 노출범죄 피해 정보는 최고 수준의 개인정보다간편인증 필수, 잠금화면 알림은 “새 소식이 있어요”로만 표시
부실 고소장 증가쉬워진 접수가 기관의 검토 부담으로 돌아올 수 있다필수 항목 검증과 제출 전 요약 확인, 누락 시 제출 제한
